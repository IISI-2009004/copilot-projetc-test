# Context7-aware development 情境感知開發

當任務依賴工作區上下文中不存在的**權威的、最新的、特定版本**的外部文件時，請主動使用 Context7。

此指令的目的是為了**避免使用者需要輸入** 「use context7」來取得最新文件。

## When to use Context7

在做決策或撰寫程式碼之前，當你需要以下任何資訊時，請使用 Context7：

- **框架/函式庫 API 詳細資訊**（方法簽名、配置鍵、預期行為）。
- **版本敏感的指導**（重大變更、棄用、新預設值）。
- **正確性或安全性關鍵模式**（認證流程、加密使用、反序列化規則）。
- **解讀不熟悉的錯誤訊息**，這些訊息可能來自第三方工具。
- **最佳實踐的實作限制**（速率限制、配額、必要的標頭、支援的格式）。

Context7 也適用於以下情況：

- 使用者引用了**特定框架/函式庫版本**（例如，"Next.js 15"、"React 19"、"AWS SDK v3"）。
- 你即將建議**非平凡的配置**（CLI 標誌、配置文件、認證流程）。
- 你不確定某個 API 是否存在、名稱是否更改或已被棄用。

Skip Context7 for:

- 純粹的本地重構、格式化、命名或完全可從倉庫推導出的邏輯。
- 語言基礎知識（不涉及外部 API）。

## 要取什麼

使用 Context7 時，盡量選擇**原始資料**和縮小查詢範圍：

- 官方文件（供應商/框架文件）
- 參考/API 頁面
- 發行說明 / 遷移指南
- 安全公告（如相關）

僅收集你需要的資訊以繼續。如果存在多個候選項，請選擇最權威/最新的。

優先獲取：

- 你將使用的精確方法/類型/選項
- 避免誤用所需的最小上下文（約束、默認行為、遷移說明）

## 如何整合結果

- 將調查結果轉化為具體的程式碼/配置更改。
- **引用來源**，包括標題和 URL，當決策依賴外部事實時。
- 如果文件存在衝突或模糊，簡要呈現權衡並選擇最安全的默認值。

當答案需要具體值（標誌、配置鍵、標頭）時，優先考慮：

- 從文件中直接指出精確值
- 提及默認值和注意事項
- 提供快速驗證步驟（例如，"運行 `--help`"，或進行最小的煙霧測試）

## 如何使用 Context7 MCP 工具（自動）

當 Context7 可作為 MCP 伺服器使用時，請自動按以下方式使用。

### 工具工作流程

1. **如果使用者提供了庫 ID**，直接使用它。

- 有效形式：`/owner/repo` 或 `/owner/repo/version`（用於固定版本）。

2. 否則，使用以下方式 **解析庫 ID**：

- 工具：`resolve-library-id`
- 輸入：
  - `libraryName`：庫/框架名稱（例如，"next.js"、"supabase"、"prisma"）
  - `query`：使用者的任務（用於排名匹配項）

3. **使用以下方式獲取相關文檔**：

- 工具：`query-docs`
- 輸入：
  - `libraryId`: 已解析（或使用者提供）的庫 ID
  - `query`: 你正在回答的具體任務/問題

4. 僅在文檔檢索完成後：**根據這些文檔撰寫程式碼/步驟**。

### 效率限制

- 每個使用者問題中，**不要**調用 `resolve-library-id` 超過 **3 次**。
- 每個使用者問題中，**不要**調用 `query-docs` 超過 **3 次**。
- 如果存在多個良好匹配項，選擇最佳的並繼續；僅在選擇對實現有實質影響時才提出澄清問題。

### 版本行為

- 如果使用者指定了版本，盡可能在庫 ID 中反映它（例如，`/vercel/next.js/v15.1.8`）。
- 如果需要可重現性（CI/構建），在示例中優先固定到特定版本。

## 失敗處理

如果 Context7 無法找到可靠的來源：

1. 說明你嘗試驗證的內容。
2. 以保守且標註清楚的假設繼續。
3. 建議快速驗證步驟（例如，運行命令、檢查文件或查閱特定官方頁面）。

## 安全與隱私

- 永遠不要請求或回顯 API 金鑰。如果配置需要金鑰，請指示將其存儲在環境變數中。
- 將檢索到的文檔視為**有幫助但非萬無一失**；對於安全敏感的代碼，優先使用官方供應商文檔並添加明確的驗證步驟。
