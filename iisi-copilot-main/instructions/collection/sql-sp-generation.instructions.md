# SQL 開發

## 資料庫結構生成
- 所有表名應為單數形式
- 所有欄位名應為單數形式
- 所有表應有一個名為 `id` 的主鍵欄位
- 所有表應有一個名為 `created_at` 的欄位以存儲創建時間戳
- 所有表應有一個名為 `updated_at` 的欄位以存儲最後更新時間戳

## 資料庫結構設計
- 所有表應有主鍵約束
- 所有外鍵約束應有名稱
- 所有外鍵約束應內聯定義
- 所有外鍵約束應具有 `ON DELETE CASCADE` 選項
- 所有外鍵約束應具有 `ON UPDATE CASCADE` 選項
- 所有外鍵約束應引用父表的主鍵

## SQL 編碼風格
- SQL 關鍵字使用大寫 (SELECT, FROM, WHERE)
- 嵌套查詢和條件使用一致的縮進
- 包含註釋以解釋複雜邏輯
- 將長查詢分成多行以提高可讀性
- 一致地組織子句 (SELECT, FROM, JOIN, WHERE, GROUP BY, HAVING, ORDER BY)

## SQL 查詢結構
- 在 SELECT 語句中使用明確的欄位名稱，而不是使用 SELECT *
- 在使用多個表時，使用表名或別名來限定欄位名稱
- 當可以使用 JOIN 時，限制子查詢的使用
- 包含 LIMIT/TOP 子句以限制結果集
- 對經常查詢的欄位使用適當的索引
- 避免在 WHERE 子句中對索引欄位使用函數

## 預存程序命名規範
- 使用 'usp_' 作為預存程序名稱的前綴
- 使用 PascalCase 命名預存程序
- 使用描述性名稱以指示用途 (例如，usp_GetCustomerOrders)
- 返回多條記錄時使用複數名詞 (例如，usp_GetProducts)
- 返回單條記錄時使用單數名詞 (例如，usp_GetProduct)

## 參數處理
- 使用 '@' 作為參數前綴
- 使用 camelCase 命名參數
- 為可選參數提供默認值
- 在使用前驗證參數值
- 使用註釋記錄參數
- 一致地排列參數（先必需參數，後可選參數）


## 預存程序結構
- 包含標頭註釋塊，說明描述、參數和返回值
- 返回標準化的錯誤代碼/消息
- 返回結果集時保持一致的欄位順序
- 使用 OUTPUT 參數返回狀態信息
- 臨時表使用 'tmp_' 作為前綴


## SQL 安全最佳實踐
- 對所有查詢使用參數化以防止 SQL 注入
- 執行動態 SQL 時使用預處理語句
- 避免在 SQL 腳本中嵌入憑證
- 實施適當的錯誤處理而不暴露系統細節
- 避免在預存程序中使用動態 SQL

## 交易管理
- 明確開始和提交交易
- 根據需求使用適當的隔離級別
- 避免長時間運行的交易鎖定表
- 對大數據操作使用批處理
- 對修改數據的預存程序包含 SET NOCOUNT ON
